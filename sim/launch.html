이직각을 앱 스토어에 내기까지

지금 게임은 HTML 파일 하나로 되어 있습니다. 이 파일을 거의 그대로 살려서 iOS와 안드로이드 앱으로 포장하는 것이 가장 빠르고 쌉니다. 혼자 진행하면 8~10주, 그중 절반은 테스트와 심사 대기입니다.

1. 어떤 방식으로 앱을 만들까

Capacitor로 포장하기추천

지금의 HTML, CSS, JS를 그대로 앱 안에 넣고, 알림·저장·진동 같은 기능만 네이티브 플러그인으로 연결합니다. 게임 로직을 다시 짤 필요가 없고, 코드 하나로 iOS와 안드로이드를 같이 냅니다. 이 게임은 화면이 가볍고 물리 연산도 없어서 웹뷰로도 성능 문제가 없습니다.

방식장점단점
Capacitor지금 코드 재사용, 로컬 알림 플러그인 있음, 두 스토어 동시Node.js 개발 환경 필요, iOS 빌드는 Mac 필요
PWA / TWA가장 간단, 안드로이드는 TWA로 플레이 스토어 등록 가능iOS 앱스토어에는 못 냄, 닫힌 앱에서 알림 예약이 어려움
Flutter / React Native완전한 네이티브 느낌게임 로직을 처음부터 다시 작성, 몇 달 걸림
Unity나중에 연출을 크게 키울 때이 게임 규모에는 과함

2. 백그라운드 진행과 알림은 앱에서 이렇게 동작합니다

이번에 넣은 설정(백그라운드 진행 여부, 속도, 알림 범위, 중요 메일에서 멈춤)은 앱에서도 그대로 씁니다. 다만 휴대폰, 특히 iOS는 닫힌 앱이 몇 시간씩 계속 돌아가는 것을 허락하지 않습니다. 그래서 앱이 실제로 돌아가는 대신 "미리 계산해서 알림만 예약"하는 방식을 씁니다.

  1. 플레이어가 앱을 닫으면, 그 순간의 게임 상태를 복사해서 설정된 백그라운드 속도로 앞으로 며칠을 미리 돌려 봅니다.
  2. 그 사이에 메일이 언제 도착하는지 실제 시각으로 바꿔서, 휴대폰의 로컬 알림으로 예약합니다. 서버나 푸시 서비스는 필요 없습니다.
  3. "중요 메일에서 멈춤"이 켜져 있으면 첫 중요 메일까지만 예약합니다. 그 이후는 플레이어가 돌아올 때까지 멈춥니다.
  4. 다시 열면 닫혀 있던 시간만큼 진짜로 진행하고, 웹 버전과 같은 "자리를 비운 동안" 요약을 보여 줍니다.

조건이 하나 있습니다. 미리 돌린 결과와 다시 열었을 때의 결과가 같아야 알림이 거짓말을 하지 않습니다. 그래서 지금 쓰는 Math.random()을 저장되는 시드 기반 난수로 바꿔야 합니다. 출시 전에 꼭 해야 하는 코드 작업 중 가장 큽니다.

  • iOS는 앱 하나가 예약할 수 있는 알림이 64개까지라, 가까운 순서로 잘라서 예약합니다.
  • 안드로이드 13 이상은 알림 권한을 따로 물어야 합니다. 첫 결과 메일이 올 때처럼 이유가 분명한 순간에 묻는 게 허락받기 좋습니다.
  • 웹 버전의 알림은 탭이 열려 있을 때만 옵니다. 앱 버전에서는 완전히 닫아도 옵니다.

3. 단계별 일정

1~2주

게임 마무리

  • 남은 밸런스 제안(1·3·5번) 결정, 시뮬레이션으로 다시 확인
  • 시드 기반 난수로 교체
  • HTML 한 파일을 게임 로직, 화면, 저장으로 나누기 (앱 포장과 테스트가 쉬워짐)
  • 저장 데이터에 버전 번호를 붙이고, 업데이트할 때 옛 세이브를 변환하는 코드
  • 첫 5분 튜토리얼: 첫 지원부터 첫 결과 메일까지 안내
3~4주

앱으로 포장

  • Capacitor 프로젝트 만들기, 저장을 기기 저장소로 옮기기
  • 로컬 알림 플러그인 연결, 2장의 예약 방식 구현
  • 앱 아이콘, 스플래시, 진동, 안드로이드 뒤로 가기 버튼 처리
  • 노치·홈 인디케이터 여백(safe area), 다크 모드, 글자 크기 확대 점검
5~7주

테스트

  • 안드로이드: 개인 개발자 계정은 테스터 12명 이상이 14일 동안 비공개 테스트를 해야 정식 출시를 신청할 수 있습니다
  • iOS: TestFlight로 지인 테스트
  • 앱을 닫았다 열었을 때 알림 시각과 실제 결과가 맞는지 집중 확인
  • 저사양 안드로이드 폰에서 20× 속도 확인
8주~

스토어 등록과 심사

  • 스크린샷(휴대폰 크기별), 짧은 소개 문구, 아이콘, 키워드
  • 개인정보 처리방침 페이지 (수집하는 정보가 없어도 링크가 필요합니다)
  • 애플 개인정보 라벨, 구글 데이터 보안 양식 작성
  • 연령 등급 설문 (IARC). 한국 출시는 스토어의 자체 등급분류로 처리됩니다
  • 심사는 보통 며칠, 처음엔 반려될 수 있으니 1~2주 여유

4. 비용과 준비물

개발 환경0원Node.js, Android Studio, (iOS는) Xcode. 지금 이 PC에는 Node.js가 아직 없습니다

5. 돈은 어떻게 벌까

무료 + 1회 결제로 전체 해금추천

예를 들어 첫 3년(게임 시간)은 무료로 하고, 4,400원 정도로 나머지와 10×·20× 속도를 엽니다. 시간을 다루는 게임이라 광고가 흐름을 끊기 쉽고, 돈을 내면 합격이 쉬워지는 구조는 이 게임의 재미를 망칩니다.

  • 유료 앱(3,300~5,500원): 가장 단순하지만, 무명 게임은 처음 다운로드가 크게 줄어듭니다.
  • 광고: "광고 보고 다음 메일까지 건너뛰기" 정도라면 어울리지만, 강제 광고는 비추천합니다.
  • 추가 콘텐츠: 새 직무(영업, 데이터 등)나 해외 취업 시나리오를 나중에 유료 확장으로 낼 수 있습니다.

6. 심사에서 걸리기 쉬운 것

웹사이트를 감싸기만 한 앱iOS 주의

애플은 웹페이지를 그대로 띄운 듯한 앱을 반려할 수 있습니다. 게임 파일을 앱 안에 넣어 인터넷 없이 돌아가게 하고, 로컬 알림과 진동처럼 앱다운 기능을 쓰면 대부분 문제없습니다.

이름과 상표확인 필요

"이직각"과 게임 속 채용 포털 "오퍼로"가 이미 등록된 상표나 실제 서비스와 겹치지 않는지 특허정보검색서비스(KIPRIS)에서 확인하세요. 게임 속 회사 이름은 무작위 조합이라 실제 회사와 우연히 겹칠 수 있으니, 실존 기업명 몇 개는 금지어로 걸러 두면 안전합니다.

알림을 광고처럼 쓰기반려 사유

"돌아오세요" 같은 알림은 스토어 정책 위반이 될 수 있습니다. 지금처럼 게임 속 메일 도착만 알리는 것은 괜찮습니다.

7. 출시 전 체크리스트

  • 밸런스 최종 확정, 시뮬레이션 리포트 갱신
  • 시드 난수, 세이브 버전 관리
  • 튜토리얼, 설정, 엔딩 수집 화면
  • Capacitor 앱 빌드 (iOS, 안드로이드)
  • 로컬 알림 예약과 복귀 시 결과 일치 확인
  • 개발자 계정 2개 개설, 본인 인증
  • 비공개 테스트 12명 × 14일
  • 스크린샷, 소개 문구, 개인정보 처리방침
  • 상표 검색
  • 심사 제출

스토어 정책과 요금은 2025년 기준입니다. 계정을 만들기 직전에 애플과 구글의 공식 안내를 한 번 더 확인하세요.
